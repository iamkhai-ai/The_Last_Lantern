# Level 05 — A Path for Two: spatial design

Source: `docs/scenario/05-a-path-for-two.md`. Scope: Level 05 only (campaign index 4). Implementation base: `64d8e63`. Vietnamese story and UI, English filenames, current character frames and existing PNG assets remain authoritative.

The user has delegated routine design decisions and asked for careful planning followed by Luna high implementation. This document records those decisions without another approval round.

## Experience and choice

Use three 640×360 rooms inside the existing CampaignScene, owned by a focused `PathForTwoLevel` controller. A single packed view would make the practice door, two relay doors and ink route compete for space; a scrolling map would require wider camera and UI changes. Local room transitions preserve the existing scene, save format and ten-level sequence. No general room engine is needed.

Flow: entry → optional safe send/arrival/recall practice → send A → enter relay → latch A on the far side → send B → enter ink room → latch B → switch off lantern/read ink → read the locked exit handle for its missing-step feedback → send C to the far end → follow the safe corridor → latch C → spiral-memory conversation (D2) → recall and wait for Lumo → E at stairs to Level 06. The practice stretch is optional (D1): A can be called at any time and the entry objective stops naming the lesson marker once A has been started. All committed doors remain usable for backtracking. No timeout, fall, reset, or loss of learned clues.

## Shared geometry contract

- Main floor foot bounds: x=24..616, y=80..310. Relay and ink have one bounded reverse-door pocket each: only the 44px opening at the southwest portal reaches y=318, with cut wall segments at y=310..318 and a solid cap from y=318 down. The pocket is walkable only while that face's A/B latch keeps its threshold open; a closed threshold blocks it. The runtime static walls, threshold body, and pure restore bounds use the same face and opening. This lets reverse-side arrivals leave the portal while keeping the rest of the HUD/out-of-room band inaccessible. Top UI ends above y=70; status/help begins y=320. Actor frame remains 36×42. Feet = center+(0,19), Arcade body 14×6 with offset (11,37), rectangle relative to center (-7,+16,14,6). Both pure geometry and actual physics consume the same rectangles.
- Main routes have at least 48px floor width. Door clear opening is 44px, with 14px actor body accounted for. Controls need reachable clear standing space; target radius normally 22px. Local interaction predicates must constrain room and intended approach side, in addition to nearest range. Revalidate on E.
- Every full standing prop silhouette footprint is solid from north/south/east/west. Do not use only the bottom few pixels of a call pedestal or standing latch. Floor pressure marks, root cables and ink are walkable. Pipe mouths in a wall use that wall's solid shape; pipes are not human passages.
- Draw stone floor from `ground_stone` and explicit masonry walls from `PATH_ROOMS[*].walls`, plus Level 05 modules. There are **no pillars** in this level: the shipped `PathForTwoLevel.drawRoom()` draws only the floor tile, the authored wall rectangles, the station schematic and the registered element/tube/cable art, so the older "existing pillars" claim is dropped rather than implemented. Do not reuse the opaque scenic base as playable geometry: its baked intake, tanks and stairs contradict these rooms. Do not regenerate/edit PNGs or character frames. Keep native aspect ratio and nearest filtering.
- Ground route, plates, ink and cables stay below feet (depth 0..7). Standing objects use 10+groundY/10. Door floor/base stays below Nhinh; header and side-post crops occlude only their actual visible strips. Never raise all actor sprites to hide layering errors. Label panels use measured prompt placement and protect current critical props and Lumo.

Coordinates below use player centers for stands/spawns and ground anchors (bottom-center) for standing art. Native call=40×48, door=64×88, latch=28×32, pressure=44×28. A door centered x with base y has bounds [x-32,y-88,64,88], 10px permanent post strips, a 44px inner opening, and a conditional lower 30px threshold. Render and collide those exact strips; the header must not occlude the whole opening. The header is visual overhead masonry; only side posts and the powered threshold collide, so a reverse-side spawn or open practice gate can be walked through.

## Repair decisions and measured numbers (2026-10-18 levels 05–10 repair, T06)

The entries below are the numbers the shipped code actually uses after the repair round; where an older
revision of this document disagreed, the code is current truth and the delta is recorded here.

- **D1 — the lesson is optional.** `callEligible('a')` no longer consults `l4-practice-complete`, and nothing writes that flag except a real recall from the lesson plate (`recallToCall`, one writer in the whole controller). The entry HUD/objective names the practice marker only until `l4-called-a` is set, i.e. until A has actually been started; H hints and the status line follow main progress afterwards. The lesson itself still teaches all four beats with shipped code (send → travel → arrival → recall), and the lesson door never closes on the player standing inside the alcove (`isPathThresholdOccupied` treats the whole alcove as occupancy, so the deleted "the lesson door is closed" recovery line is gone).
- **D2 — the memory stays at latch C.** The seven-line spiral exchange plays when the exit latch commits, and the wall engraving replays it afterwards; it is not moved into Lumo's travel-back beat just to match an older description. `l4-memo` is written when the dialogue completes, and the exit objective names the spiral while the memory is unread.
- **Latch C before the ink.** `latch-c` is always enabled inside the ink room, so a locked mechanism still gives useful feedback instead of disappearing: the refusal names the missing step in flow order (door B not latched → lantern still on / the ink trail not walked → Lumo not yet at plate C), and an early E never writes `l4-latch-c`.
- **Reunion objective.** It names the control the player must use ("Nhấn E ở tay gọi C…") and reports Lumo's real state: travelling → "Lumo đang về…", arrived → "Lumo đã về tới nơi…".
- **Held-E guard across a room change.** A transition arms `interactReleasePending` before the new room registers anything; every door prompt, door enabled test and door action is refused while E is still down, and the guard clears when the key comes back up. The room rebuild also clears the interaction registry, which nulls the active target, so a held press cannot act twice through a threshold.
- **Return arrival, measured.** `PATH_BACK_ARRIVAL_OFFSET = 40`, i.e. returning through A or B lands at **(480,250)**: 29px from the door stand (480,221) r24 — outside the trigger — while (480,250) is walkable floor connected to the hall in both rooms. The old `+20` (480,230) was 9px from the same stand, i.e. inside the trigger, and is the ping-pong this replaces.
- **Checkpoints, room-aware.** `PATH_CHECKPOINTS` names one reached-side point per room (entry `entry-hall` (180,280), relay `relay-hall` (110,251), ink `ink-foyer` (82,251)). The old single (180,280) fallback clipped the relay and ink wall bands and is asserted unreachable.
- **Ink mark.** One 348×48 tile over the whole corridor at (358,242), drawn and place-checked from the layout's own corridor rect `PATH_INK_CORRIDOR` = (184,218,348,48): the two 348px masonry slabs that flank the band are derived from that same rect, so the tile, the walkable band and the masonry cannot disagree. The two 240×48 stamps 132px out of phase are gone.
- **Cables and elbows.** Every authored route line (`PATH_ROUTE_LINES`, chords 205–380px) is covered end to end by ≤160px native cable stamps along the real waypoints, and genuine corners get the elbow module instead of a straight piece across the bend. Each line is authored as its `lead` (from the line's own anchor to where the walk joins it) plus its `plate` leg; the renderer draws both, and Lumo's walk inside the plate's room **is** the `plate` tail (`getPathLocalLeg`), not a second copy of the same coordinates. The between-room pipe legs still author their turn points in `PathForTwoLevel.pipeRoute()`, and `check-path-for-two.mjs` case `the_controller_route_legs_run_along_the_authored_lines` fails if any of them stops being a run of the authored lines (verified by mutation: shifting one pipe point by 1px turns the case red).
- **Lens measurement for latch C / door C.** With the shipped selector: (559,198) selects latch C — the opted-in owner keeps the position against the nearer door — and (567,208) selects door C. Latch C then keeps 92 reachable positions and door C 100 of the ink room's legal stands, and each answers from its own authored stand (550,218) / (574,188). Both coordinates therefore stay as authored; the review's proposed (578,190) is not used as evidence that the overlap is gone.
- **Write-only flags retired.** `pendingClose` (a private field written and never read; the deferred close is `body.enable` per frame) and `l4-lumo-arrived` (written on route completion, read nowhere in the repository at `ee34eba`) were deleted after confirming no reader, external or internal, exists. No compatibility shim is owed.

## Lumo, doors and saves

- Controller owns all Level 05 Lumo updates; skip legacy CampaignScene Level05 `called/at` update logic and generic beams/props/controls. Pass existing Lumo actor through the focused controller interface; do not change Lumo behavior in other levels.
- Use explicit assignment follow/practice/a/b/c and authored pipe waypoints with room IDs. Move the real sprite along these points, compensating for Lumo.update's (+18,-12) hover target. Room-hop only at matching authored pipe endpoints; hide the sprite when its simulated room differs from the player's room. Draw native tube modules and stateful cable art along the authored route lines (`PATH_ROUTE_LINES`): the renderer draws each line's `lead` and `plate`, Lumo's own walk inside the plate's room is that same line's `plate` tail (`getPathLocalLeg`), and its between-room pipe legs author their own turn points which `check-path-for-two.mjs` case `the_controller_route_legs_run_along_the_authored_lines` asserts are runs of those lines — so the art, the walk and the checks read one list of waypoints instead of two lists that have to stay equal. Movement continues remotely, allowing real arrival without teleporting at command time. No elapsed-time power flags.
- A live plate requires matching assignment, matching simulated plate room and actual sprite proximity. Called/at history is never sufficient. Recall loses unlatched power immediately. When the foot body overlaps an open threshold, defer closure until it leaves; if power returns meanwhile clear pending closure. Occupancy protects only that threshold, not a permanent latch.
- Store Level05 room/assignment/route progress under `l4-*` flags/counters, not the Observatory-only `roomId`. Preserve existing `l4-latch-a/b/c`, `l4-ink-revealed`, `l4-memo`, `l4-return-called`, `l4-reunited`, called/at compatibility and v1 save key. New state can be local to this controller. Clear generic route coordinates when finally leaving Level05 so Level06 does not inherit this assignment.
- Normalize durable latch hierarchy C→B→A and B→A without erasing achievements. Legacy saves without local room metadata choose ink for B/C, relay for A, otherwise entry. Reconstruct an old assignment from latest relevant called mark if not reunited; sanitize coordinates and re-evaluate actual arrival. Unknown room/assignment data falls back safely.
- Restore room/state/Lumo first, derive gates, then choose reachable player checkpoint using the same body/solids. Reject saved positions in masonry, full props, posts, a now-closed threshold, or a room beyond an unsolved door. A saved legitimately traversed room with an unlatched entrance remains recoverable using its far-side control; do not remove that progress. Named room-entry/call/latch/corridor-end checkpoints never bypass unsolved gates. Save room changes and route changes atomically with coordinates.

## Feedback, story and completion evidence

All complete scenario dialogue must be present at its appropriate beat, including opening, practice arrival, latch-A role exchange, ink observation, beckoning at corridor end, seven-line memory, hints and three-line ending. H advances through the scenario's three helpful levels without recalling Lumo. J retains learned calling/ink/memory facts and current assignment. HUD gives current room, next physical action and travelling/arrived/held status; it cannot claim arrival from a command. Prompt placement must protect active call/latch/door art and actors.

Required checks: production build; focused geometry/state checks for four-direction solids, reachable intended-side stands, graph reachability of every stage, thresholds losing power while occupied, actual arrival/recall, legacy/current safe restore and correct next-level index. `scripts/check-path-for-two.mjs` runs those as one counted set (20 cases) and **exits non-zero whenever any case fails**, naming it on the summary line; a failing case can no longer print "passed" and exit 0. The contract cases a reviewer should look for by name: `geometry_and_state_invariants`, `the_whole_lesson_still_teaches_send_travel_arrival_and_recall`, `skipping_the_lesson_still_lets_the_player_call_A`, `the_objective_follows_the_main_progress_once_A_has_started`, `the_C_handle_answers_before_the_ink_is_found`, `the_reunion_objective_names_the_C_handle_and_lumos_travel`, `the_lesson_door_never_closes_on_the_players_feet`, `the_four_sides_of_every_standing_prop_are_quiet`, `every_standing_prop_answers_only_from_its_own_face`, `door_controls_answer_only_from_their_own_room_side`, `a_held_E_cannot_ping_pong_through_the_door_just_used`, `route_cables_reach_both_ends_and_bend_at_real_corners`, `the_controller_route_legs_run_along_the_authored_lines`, `the_ink_mark_is_one_continuous_run_and_the_mouths_leave_the_passages`, `the_spiral_engraving_sits_on_the_wall_with_a_reachable_stand`, `the_small_schematic_comes_from_the_same_layout_data`, `every_door_swap_lands_on_walkable_floor_that_leads_back`, `the_two_write_only_flags_stay_retired`, `restore_fallbacks_are_named_safe_checkpoints`, `saved_positions_restore_safely_in_every_room_and_state`. `scripts/check-interaction-targets.mjs` measures the latch C / door C lens with the shipped selector. Inspect runtime visuals on a separate localhost origin if browser tooling is available; in this environment it is not, so the browser item is `NOT_RUN` with that reason and no substitute probe is offered as a playthrough. Never touch the player's existing save. Human end-to-end puzzle acceptance remains the user's review.
